# Proposal: List All Slugs

## Intent

Add a `GET /slugs` endpoint to expose all registered short codes in the database. Users currently have no way to discover what slugs exist without querying the database directly. This enables listing, auditing, and building management UIs on top of the shortener.

## Scope

### In Scope
- New sqlc query `ListSlugs` returning all rows from `urls` table
- New store method wrapping the sqlc query
- New service method delegating to store
- New handler `HandleListSlugs` returning JSON array
- Register `GET /slugs` route on the Chi router
- Unit tests at handler and service layers
- Integration tests at store layer

### Out of Scope
- Pagination (cursor or offset-based) — deferred to a follow-up change if needed
- Filtering or search by slug/URL
- Authentication or authorization on the listing endpoint
- Admin-only access restrictions

## Capabilities

### New Capabilities
- `url-listing`: List all registered short codes with metadata (slug, original URL, click count, created at)

### Modified Capabilities
None — existing specs (url-creation, url-redirect, url-stats) are unaffected.

## Approach

Simple flat list following existing three-layer patterns:

1. **SQL**: `SELECT slug, original_url, click_count, created_at FROM urls ORDER BY created_at DESC`
2. **Store**: `ListSlugs(ctx) ([]SlugEntry, error)` wrapping sqlc-generated query
3. **Service**: `ListSlugs(ctx)` delegating to store (thin pass-through, consistent with existing pattern)
4. **Handler**: `HandleListSlugs` — map domain types to JSON response, return `[]` (not `null`) on empty
5. **Route**: `r.Get("/slugs", h.HandleListSlugs)` — static segment coexists safely with `GET /{slug}` due to Chi's radix tree priority

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Route conflict with `GET /{slug}` | Low | Chi radix tree prioritizes static `/slugs` over parameterized `/{slug}`; add explicit handler test |
| Unbounded response at scale | Low | URL shorteners rarely exceed thousands of rows; pagination is a clean follow-up |
| Empty list returns `null` instead of `[]` | Low | Handler initializes slice before marshaling; add test for empty case |

## Rollback Plan

Remove the `GET /slugs` route registration in `routes.go` and delete the handler method. The sqlc query and store method can remain (unused) or be reverted via `sqlc generate`. No database migration involved — purely additive code.

## Dependencies

None — no new libraries, no schema changes, no external services.

## Success Criteria

- [ ] `GET /slugs` returns 200 with JSON array of all slugs
- [ ] Empty database returns `[]` (empty array, not `null`)
- [ ] Response includes `slug`, `original_url`, `click_count`, `created_at` per entry
- [ ] Existing `GET /{slug}` redirect continues to work unchanged
- [ ] Unit tests pass at handler and service layers
- [ ] Integration tests pass at store layer
